01

¿Qué es un Trigger?

Es un objeto de base de datos que contiene un conjunto de instrucciones SQL que se ejecuta de manera automática en respuesta a un evento específico (DML, DDL o de inicio de sesión).

02

¿Cuál es su Propósito?

Garantizan la integridad referencial compleja, automatizan tareas repetitivas de cálculo, evitan transacciones no deseadas, mantienen logs de auditoría activa y sincronizan tablas de forma transparente.

03

Ventaja del Motor

Al ejecutarse directamente dentro del motor de SQL Server, evitan el tráfico de red de ida y vuelta que causaría realizar estas comprobaciones y flujos en el backend de la aplicación.

Módulo Interactivo

Arquitectura de Tablas Virtuales

SQL Server administra dos tablas lógicas y temporales exclusivas durante la acción de un disparador: inserted e deleted. Su comportamiento cambia drásticamente según la operación DML efectuada.

Paso 1: Acción DML

Insertar Registro

Se ejecuta un comando INSERT sobre la tabla.

➔
➔
inserted
Activa (Nuevo Dato)
deleted
Inactiva (Vacía)
Paso 3: Disparo

Trigger se Ejecuta

El Trigger lee inserted para validar, auditar o replicar la información.

💡
Comportamiento Técnico Detallado:

Durante un INSERT, la tabla inserted almacena una copia exacta de las filas que se pretenden ingresar. La tabla deleted no se utiliza y permanece completamente vacía.

Clasificación de Triggers

¿Cuándo, cómo y sobre qué elementos de base de datos se disparan?

Por Momento de Ejecución (Timing)

¿En qué fase de la consulta se interponen?

AFTER / FOR Triggers

Por Defecto

Se ejecutan después de que la acción de la consulta (INSERT, UPDATE, DELETE) haya pasado las restricciones de integridad (como Foreign Keys y Check Constraints) y se guarde temporalmente.

CREATE TRIGGER trg_Name ON Tabla AFTER INSERT ...

INSTEAD OF Triggers

Pre-acción

Se ejecutan en lugar de la acción original. El motor cancela la acción DML original del usuario y ejecuta únicamente el cuerpo de instrucciones dentro del disparador. Ideal para vistas no actualizables de forma nativa.

CREATE TRIGGER trg_Name ON Vista INSTEAD OF UPDATE ...

Por Tipo de Evento (Alcance)

¿Qué tipo de eventos interceptan?

1. DML Triggers

Operaciones de manipulación de datos en tablas y vistas.

INSERT UPDATE DELETE

2. DDL Triggers

Cambios estructurales en el esquema de la base de datos.

CREATE ALTER DROP

3. LOGON Triggers

Control de accesos y sesiones de usuarios de base de datos.

CONEXIONES SESIONES
⚠️ Nota Técnica: En SQL Server, los triggers DML por defecto operan a nivel de sentencia (Statement), ejecutándose una sola vez por consulta incluso si se modifican millones de filas juntas.

Ejemplos Prácticos de Implementación

Caso Seleccionado

Validación de Fechas de Envío (Northwind)

Este trigger de tipo AFTER INSERT, UPDATE en la tabla Orders valida que la fecha de envío (ShippedDate) no sea cronológicamente anterior a la fecha de compra o pedido (OrderDate).

✔ Evita inconsistencias de fechas de negocio.
Comandos Clave Utilizados:
  • • ROLLBACK TRANSACTION: Revierte la transacción si falla.
  • • RAISERROR: Muestra error personalizado al cliente.
  • • EXISTS: Evalúa si hay registros inconsistentes.
Taller3.3_SQLServer.sql 
-- Trigger para validar fechas de envío coherentes
CREATE TRIGGER trg_Validar_Fecha_Envio
ON Orders
AFTER INSERT, UPDATE
AS
BEGIN
    SET NOCOUNT ON;

    -- Si detecta que ShippedDate es menor que OrderDate
    IF EXISTS (
        SELECT 1 
        FROM inserted 
        WHERE ShippedDate < OrderDate
    )
    BEGIN
        -- Eleva el error y cancela todo cambio
        RAISERROR ('Error: La fecha de envío no puede ser anterior a la fecha del pedido.', 16, 1);
        ROLLBACK TRANSACTION;
    END
END;

Conclusiones del Estudio

01

Garantía de Integridad

Los triggers permiten forzar restricciones complejas y dinámicas que las claves primarias/foráneas básicas no pueden expresar por sí solas.

02

Auditoría Robusta

Al rastrear los datos de deleted e inserted, se puede registrar de forma transparente qué usuario hizo qué cambio exacto.

03

Rendimiento Interno

Optimiza la gestión al ejecutarse del lado del servidor SQL, evitando múltiples envíos y consultas por red desde las aplicaciones clientes.

04

Consistencia del Negocio

Permiten automatizar la actualización de stocks, sumas o estadísticas de ventas en tiempo real tras cada pedido o compra exitosa.
