AeroGest Cusco

Transformando la gestión aeroportuaria mediante un modelo de datos robusto y Design Thinking.

Universidad Andina del Cusco • Ingeniería de Sistemas • Modelado de Base de Datos

El Paradigma Anterior: "Ver"

El sistema original era un BI estático. Los gerentes solo podían observar gráficas del pasado, reaccionando tarde a los problemas operativos.

  • Visualización estática de vuelos.
  • Bitácoras de incidencias manuales.
  • Maletas procesadas sin control de tiempo real.

Nuestra Propuesta: "Hacer"

Transformamos la interfaz en una consola operativa activa. Ahora el gerente toma decisiones instantáneas para mitigar crisis.

  • Tableros Kanban interactivos para mantenimiento.
  • Reasignación dinámica de puertas de embarque.
  • Simulador predictivo (What-If) impulsado por IA.

El Motor de la Transformación: SQL Server

Para que AeroGest Cusco deje de ser un panel de lectura y pase a gestionar operaciones en tiempo real sobre una base histórica de 10,000 registros, diseñamos una arquitectura de datos optimizada.

1. Del Concepto a la Física

Refinamos las entidades del aeropuerto (Aerolíneas, Vuelos, Incidencias, Equipajes). Tradujimos nuestro modelo lógico a un esquema físico relacional en SQL Server mediante scripts DDL generados en SSMS, definiendo tipos de datos precisos para optimizar el almacenamiento.

1
Impacto en AeroGest

Garantiza la integridad de los datos cuando el gerente arrastra y suelta (Drag-and-Drop) vuelos en el nuevo Gantt Operacional.

Impacto en AeroGest

Alimenta la "Fase 1" (Quick Wins) descubriendo patrones de demanda y saturación en microsegundos.

2. Lógica y Álgebra Relacional

Poblamos las tablas con los 10,000 registros históricos respetando restricciones lógicas. Utilizamos Álgebra Relacional y subconsultas complejas para extraer la información vital que requieren los módulos analíticos.

3. Automatización (Procedures & Triggers)

Implementamos Procedimientos Almacenados para encapsular lógicas complejas como el simulador de escenarios. Añadimos Triggers (Disparadores) a nivel de base de datos para monitorear eventos en tiempo real y proteger la consistencia de los estados operativos.

3
Impacto en AeroGest

Hace funcionar el Monitor SLA: Los triggers detectan si una maleta excede los 20 min y emiten una alerta visual inmediata.

El Despliegue Final

Despliegue en DataCenter

Toda la estructura física y lógica de la base de datos fue alojada de manera centralizada, asegurando alta disponibilidad para el Centro de Comando Aeroportuario.

Respuesta en Tiempo Real

El modelo lógico optimizado permite despachar incidencias (Kanban) y calcular déficit de personal instantáneamente sin colapsar el sistema.

Escalabilidad (Fase 3)

Base de datos lista para escalar y procesar las predicciones del modelo cognitivo (Gemini 2.5) en la simulación de contingencias extremas.
