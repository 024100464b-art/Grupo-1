1
Fase 1: Empatizar y Definir

Entendiendo el Caos del Equipaje

Para sumergirse en la problemática aeroportuaria, se aplicaron encuestas estructuradas utilizando Google Forms y se consolidaron las respuestas directamente en Google Sheets. El objetivo: mapear los cuellos de botella en la entrega de equipajes en Cusco.

Hallazgos Clave

  • ✓ Sincronización ineficiente entre vuelos entrantes y fajas operativas.
  • ✓ Pasajeros desorientados por falta de pantallas dinámicas actualizadas.
  • ✓ Personal de rampa trabajando bajo presión climática sin alertas integradas.

Definición del Reto (POV)

¿Cómo podríamos optimizar la visualización de datos operacionales de vuelos y asignación de equipajes para que el personal de rampa reduzca los tiempos de entrega en un 30%?

2
Fase 2: Idear

Concibiendo AeroQuery Cusco

Se propuso un sistema web responsivo que sirviera como único punto de verdad operativa. La solución ideada integra seguridad, monitorización climática, consultas inteligentes avanzadas y asignación automatizada.

3
Fase 3: Prototipar (Google Stitch)

Estructurando la Interfaz del Mañana

Utilizando **Google Stitch**, el equipo materializó la interfaz visual de alta fidelidad, diseñando flujos simplificados para que el personal en pista acceda a la información con menos de tres clics.

Principios del Diseño AeroQuery:

  • 🔵 Paleta Aeronáutica: Azul profundo y celeste cielo para transmitir confianza y claridad técnica.
  • 📱 Diseño Mobile-First: Cards adaptables a pantallas pequeñas en la pista de aterrizaje.
  • 👁️ Legibilidad Alta: Contraste optimizado para exteriores soleados.

// SCHEMA EXPORTADO: 
CREATE TABLE fajas (
  id SERIAL PRIMARY KEY,
  estado VARCHAR(20) CHECK (estado IN ('libre', 'ocupado', 'mantenimiento'))
);

CREATE TABLE vuelos (
  id SERIAL PRIMARY KEY,
  aerolinea VARCHAR(100),
  estado VARCHAR(50),
  faja_id INT REFERENCES fajas(id)
);
