1. Introducción y Problema que Resuelve

AeroQuery resuelve el problema de la gestión operativa en terminales aéreos complejos. Los sistemas aeroportuarios manejan simultáneamente a pasajeros, boletos, personal de mantenimiento, distribución de equipaje y el tracking de los vuelos.

El sistema centraliza estos datos en una base de datos relacional de 13 tablas perfectamente normalizadas y provee una aplicación de escritorio dinámica e interactiva en Windows Forms. Esto permite extraer métricas instantáneas (como rutas más transitadas, recaudación económica por aerolíneas y logística de peso de equipaje) para agilizar la toma de decisiones gerenciales.

2. Modelado de Base de Datos (SQL Server)

Para soportar la complejidad operativa y asegurar la integridad de la información, se diseñó e implementó la base de datos BDAeropuertoCusco en Microsoft SQL Server con 13 tablas:

  • 🏢 Entidades Principales: Aeropuerto, Aerolínea, Aeronave, Puerta Embarque.
  • ✈️ Operatividad Aérea: Vuelo.
  • 🎟️ Gestión Comercial: Pasajero, Boleto, Asiento, Equipaje.
  • 👥 Recursos Humanos: Cargo, Área, Empleado, Vuelo Empleado.

Normalización e Integridad

Todas las tablas poseen una Llave Primaria (IDENTITY autoincrementable) y se establecieron múltiples Llaves Foráneas para garantizar la integridad referencial.

Simulación: 10,000 pasajeros y 900 vuelos generados mediante WHILE.

3. Implementación del ORM: Entity Framework Core

Se implementó Entity Framework Core como capa de acceso a datos para garantizar seguridad y mantenimiento rápido.

  • Ingeniería Inversa (Scaffolding): Se utilizó la herramienta CLI dotnet-ef para leer el esquema de SQL Server. Esto generó automáticamente las 13 clases en C# y el contexto BdaeropuertoCuscoContext.
  • Navigation Properties: EF mapeó automáticamente propiedades complejas. Desde un objeto Equipaje, es posible navegar hasta el nombre del Pasajero o la ciudad del AeropuertoDestino.

5. Lógica y Funcionamiento del "Core" (Las 10 Consultas)

El botón "Ejecutar" del menú dispara un bloque lógico que, mediante LINQ to Entities, transforma las peticiones C# en consultas SQL altamente optimizadas.

Nivel 1 Consultas Básicas

  • 1. Listar todos los Aeropuertos: Muestra el catálogo de infraestructura (.ToList()).
  • 2. Buscar Pasajero: Un filtro Where(p => p.NroDocumento == dni) que recibe el parámetro ingresado.

Nivel 2 Consultas Intermedias

Uso de Navigation Properties para evitar JOINs manuales.

  • 3. Vuelos, Aerolíneas y Aeronaves: Usa doble Include() para mostrar nombres en vez de IDs numéricos.
  • 4. Boletos Activos y Pasajeros: Cruza las tablas Boleto y Pasajero para mostrar nombres completos.
  • 5. Personal y Áreas de Trabajo: Detalla a los empleados con su Cargo y Área.
  • 6. Filtro de Vuelos Retrasados: Aplica filtro (Estado == "Cancelado" || Estado == "Retrasado").

Nivel 3 Consultas Avanzadas

Extracción de métricas cruzando entre 3 y 5 tablas.

  • 7. Recaudación por Aerolínea: Usa GroupBy() y Sum(b => b.Precio) cruzando Boleto -> Vuelo -> Aerolinea.
  • 8. Rutas más Demandadas: Agrupación compuesta por Ciudad Origen y Ciudad Destino, con Count() para rankear.
  • 9. Peso de Equipaje por Vuelo: Agrupa por código de vuelo sumando Sum(x => x.Peso) para logística aeronáutica.
  • 10. Dashboard de Ocupación: La más exigente. Une 4 tablas base y proyecta objetos anónimos en tiempo real comparando Capacidad Total contra Boletos Vendidos.

CREATE DATABASE BDAeropuertoCusco;
GO

USE BDAeropuertoCusco;
GO

-- 1. ENTIDADES PRINCIPALES
CREATE TABLE Aeropuerto (
    IdAeropuerto INT IDENTITY(1,1) PRIMARY KEY,
    Nombre VARCHAR(100) NOT NULL,
    Ciudad VARCHAR(50) NOT NULL,
    Pais VARCHAR(50) NOT NULL
);

CREATE TABLE Aerolinea (
    IdAerolinea INT IDENTITY(1,1) PRIMARY KEY,
    NombreComercial VARCHAR(100) NOT NULL,
    CodigoIATA CHAR(2) NOT NULL
);

-- 2. OPERATIVIDAD AÉREA
CREATE TABLE Vuelo (
    IdVuelo INT IDENTITY(1,1) PRIMARY KEY,
    IdAerolinea INT FOREIGN KEY REFERENCES Aerolinea(IdAerolinea),
    IdAeropuertoOrigen INT FOREIGN KEY REFERENCES Aeropuerto(IdAeropuerto),
    IdAeropuertoDestino INT FOREIGN KEY REFERENCES Aeropuerto(IdAeropuerto),
    FechaHoraSalida DATETIME NOT NULL,
    Estado VARCHAR(20) -- 'Programado', 'Retrasado', 'Cancelado'
);
